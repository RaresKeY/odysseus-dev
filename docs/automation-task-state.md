# Automation state and compact selection

`src/automation_task_state.py` separates server lifecycle facts from historical
request/answer evidence. Only an unexpired unresolved server card is pending;
completed prose cannot create a pending question or permission. Terminal
submissions cannot be revived by a late stream cleanup. Preparation needs its
matching live lease; admitted execution releases that lease deliberately.

`src/automation_catalog.py` retains exact membership between compact choice
descriptions and inert proposed operations. It copies the candidate snapshot,
rejects non-JSON/live handles and enforces a hard UTF-8 packet budget without
silently truncating the ask or dropping offered membership. Ranking and model
selection still grant no permission; canonical dispatch checks every action.

These mechanics adapt the earlier Jev concern-series lifecycle/catalog
acceptance corrections. The earlier whole-catalog tool selection, fixed Jev
model, native-only loop and old broad approval policies are not copied into
chat execution policy. Historical fixture scores remain small-sample evidence.
